# Постановка задачи по интерфейсу мониторинга ALT Orchestra кластера

Основные моменты:

- интерфейс ориентирован на сервис `apid`, функционирующий на каждом узле кластера и доступный по порту `50000` через GRPC API интерфейс;
- доступ к сервису `apid` через команду `talosctl` с выводом информации в формате `json`; 
- получение части данных по кластеру через команду kubectl с выводом информации в формате `json`;
- проверка наличия порта на узле командами nmap (с выводом информации в формате `XML`), curl.

## Параметры команды

### --talosconfig

Для команды talosctl необходимо наличие файла YAML-файла `talosconfig` содержащий:

- текущий контекст (context);
- список поддерживаемых контекстов (contexts). Каждый контекст содержит:

    - endpoints;
    - ca, crt, key ключи.
    
Путь до файла `talosconfig` передается параметром  `--talosconfig`.

### --net IP/mask[,IP/mask]...

Параметр `--net IP/mask>[,IP/mask]` указывает маску сети, где находятся узлы кластера.
Может быть указано несколько сетей.

### -e endpoint[,endpoint]

Список endpoint'ов.
Данный параметр можно не указывать, если в файле `talosconfig` они указаны в `.contexts.имя_кластера.endpoints` они указаны.


## Запуск команды

При вызове команды с помощью
```
nmap -p 50000 -n -oX - IP/mask  
```
производится сканирование всех указанных подсетей для определения списка узлов, на которых запущен сервис `apid`.
