# Постановка задачи по интерфейсу мониторинга ALT Orchestra кластера

## Преамбула

В настоящее время не существует некоммерческого пользовательского интерфейса (далее UI) для работы с Talos-кластером.
Соображения qwen по этом вопросу приведены на странице [talosUI](https://altlinux.space/kaf/maestro/src/branch/main/talosUI.md).

Проект [OMNI](https://docs.siderolabs.com/talos/v1.11/platform-specific-installations/omni) предполагает варианты либо централизованной поддержки (Omni Cloud SaaS), либо локальной установки, но оба варианта коммерческие и для работы в рамках одного датацентра избыточные, так как предполагают поддержку различные облачных провайдров вне Российской юрисдикции.  





Управление кластером  и его мониторинг через talosctl довольно трудоемко.
Достаточно сказать, что команда `talosctl` поддерживает несколько десятков команд,
команда `talosctl get`
поддерживает 151 подкоманду из 18-ти групп.
Запомнить их практически невозможно. 

Список подкоманд `talosctl get` с разбивкой на группы приведен на странице [RDTree.yaml](https://altlinux.space/kaf/maestro/src/branch/main/RDTree.yaml).

Вывод основных подкоманд - на странице [usefullSubcommands.md](https://altlinux.space/kaf/maestro/src/branch/main/usefullSubcommands.md).
 
Описываемая программа Maestro являясь оболочкой над программой `talosctl` поддерживает UI для:
- разворачивания ALT Orchestra / Talos кластера;
- мониторинга состояния узлов ALT Orchestra / Talos кластера (стадия разворачивания узла, список и состяния оборудования, потребляемые ресурсы, сетевые ресурсы,  и т п);
- добавление или удаления узлов из кластера;
- обновления как версии ALT Orchestra / Talos кластера, так и версии kubernetes;
- ...

## Описание интерфейса

TopLeft кнопка будет отображать список контекстов (context - имя кластера) и позволять переходить с одного кластера на другой
Остальные (юолее правые по отношению к topkeft) будут перерисовываться при переходе на другой кластер

maestro будет периодически сканирвать указанные ей подсетки на предмет наличитя узлов ALT Orchestra / Talos.
Узлы определяются по наличии на них порта 50000, который прослушивает systemd-сервис APID.

Получив список узлов через `talosctl get info` определся к какому кластеру принаждлежит каждый узел.
В результате строится дерево
- кластер1
  * controlplane узлы
  * worker-узлы
- кластер2
  * controlplane узлы
  * worker-узлы
...

Если `talosctl get info` молчит, значит узел не принадлежат ник одному из кластеров, находится в состоянии Maintenence - ожидания разворачивания.

При наличии таких узлов:
- в списке кластеров будет появляться выбор New, позволяющий собрать новый кластер из новых узлов  
- появится кнопка Add, позволяющая добавить к существующим кластерам новые узлы.

При появлении новых узлов или исчезновении существующих узлов в интерфейсе появляется сообщение об этом.

При выборе кластера в top-строке появляется кнопка `Nodes`, нажав на которую можно будет выбрать интересующтй узел.
При выборе  узла появляется подменю групп подкоманд команды `talosctl get` (первый уровень YAML-файла [RDTree.yaml](https://altlinux.space/kaf/maestro/src/branch/main/RDTree.yaml)).
При выборе группы в подменю отображается список подкоманд группы.
При выборе подкоманды нв экране отображается вывод команды с периодическим обновлением.
При этом подкоманда для получения полной информации вызывается с флагом `-o json` или `-o yaml`.
Вывод  в указанных фломатах парсится и на экране отображается скомпонованные данные. 

В процессе разработки к интерфейсу будут добаввляться дополнительные кнопки и функционал. который поддерживают
команды `talosctl`, описанные нас странице [CLI интерфейс talosctl](https://docs.siderolabs.com/talos/v1.11/reference/cli).  

Кроме этого в дальнейшем возможно доаьыление поддерэки разворачивания узлов через `Cloud API` в облачныъ средах (PVE, Yandex Cloud, VK Cloud, ...) с генерацией артефактов через [image-factory](factory.altlinux.space).

## Основные моменты:

- интерфейс ориентирован на сервис `apid`, функционирующий на каждом узле кластера и доступный по порту `50000` через GRPC API интерфейс;
- доступ к сервису `apid` через команду `talosctl` с выводом информации в формате `json`; 
- получение части данных по кластеру через команду kubectl с выводом информации в формате `json`;
- проверка наличия порта на узле командами nmap (с выводом информации в формате `XML`), curl.

## Параметры команды

- --context - параметр содержит имя кластера из списка поддержиывемых который будет мониториться. 

- --net IP/mask[,IP/mask]... - параметр описывает список подсетей в которых производится сканироание узлов кластеров.
